Offshore Investigator

Ask how two records in the public ICIJ Offshore Leaks data are connected. The answer is a path through a FalkorDB graph — ranked by an explainable connection relevance score, and shown down to every hop and source record.

Checking connections by hand across companies, officers, intermediaries and addresses in different jurisdictions is slow cross-referencing. Here the graph does the reasoning — Cypher searches, prunes high-degree hubs and scores each path — while the language model only picks tools and writes the summary.

What it does

Hub-aware multi-hop paths

Exact-depth path search with the hub predicate on every intermediate hop. Each path gets an explainable connection relevance score — the mean rarity of its intermediate nodes — with a per-node breakdown.

Every answer shows its path

The full path, relationship types, source record IDs, node degrees, excluded hubs, the tool trace and the Cypher behind it — all from the same query result. No second database.

Ambiguity is asked, never guessed

When a name matches several records, the agent lists the candidates with labels, countries and degrees and waits for your pick. A pinned record is deterministic — it is never silently chosen.

Possible matches stay possible

Soft edges (similar, same_as, underlying) render dashed and are always labelled “possible match”. They are never presented as a confirmed identity.

Read-only MCP server

Fixed, purpose-built graph tools — search, pathfinding, shared neighbours and expansion — parameterized, depth-bounded and size-capped (no generic text-to-Cypher). A second, external MCP client answers from the same server (verified).

Ranked paths and expansion

Multiple ranked paths per question, an unfiltered reference path when a hub changed the answer, and click-to-expand neighbours on any node, straight from the graph.

How it works

1
You ask

“What is the strongest recorded connection between two names?”

2
Name search

The agent resolves names to records — one at a time, asking when ambiguous.

3
Graph tools

Read-only MCP tools run bounded, parameterized Cypher traversals.

4
Score and path

Hubs are pruned inside the traversal; the rarity-weighted score and every degree come back with the path.

5
Explanation

The model turns structured results into plain language — pathfinding, filtering and scoring stay in Cypher plus code.

The graph data model.

Core edges connect the four labels; soft edges are separate relationship types, opt-in semantics, and always labelled a possible match. The 1,139 IDs that ICIJ reuses across the officer and intermediary files are stored as one node with both labels — verified identical names and country codes in all 1,139 cases. Every edge keeps its raw link text, a normalized role category, dates and sourceID.

Why the graph is essential

The test used throughout the design: if removing FalkorDB leaves a feature working, that feature is wrong. The hub filter lives in the Cypher MATCH pattern, so high-degree nodes are pruned while expanding, not after; a post-hoc filter over an unfiltered path list timed out at 60 s next to the 36k-degree hub, while the in-traversal prune returns in milliseconds. Everything on the screen — degrees, edge fields, the score breakdown — is a returned path.
