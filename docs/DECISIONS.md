## D1 FalkorDB is central. If a feature works without it, the feature is wrong.
## D2 Hub awareness
Degree = how informative a link is, not whether a record is legitimate. Filter is configurable by node type, can be overridden by the user, and excluded hubs are shown in the explanation when they change the result. Degree = distinct neighbors, stored at import (core-only and all-edges counts).
## D3 Rarity-weighted relevance score
weight(v) = log((N + 1) / (degree(v) + 1)), N = nodes in the relevant population, degree over distinct neighbors. It is a connection relevance score, NOT a probability of kinship or wrongdoing. Show contributing nodes, edge types and degrees. Generate candidate paths with the hub filter inside the Cypher traversal, then rank the small set in Python. Do not assume FalkorDB has weighted shortest path: check the docs and test the installed version.
## D4 ID overlap policy: CONFIRMED option (a) — one node per ID with both labels
Evidence (Offshore Leaks slice): 1,139 IDs in both files (0.4% of nodes); all share identical normalized names, country_codes and sourceID; 53,011 in-slice edges (9.4%) touch them (43,304 officer_of + 8,450 intermediary_of + 1,193 registered_address + 64 soft), including the #2 hub Portcullis TrustNet (BVI) Limited (degree 36,254); in-slice type/role mismatch 0/0. Option (b) would delete real connectivity, so (a) wins. Never choose a record from rel_type alone. Store officer_name / intermediary_name separately ONLY when they differ, with name_mismatch=true (none differ in this slice). Verified on the Offshore Leaks slice ONLY — re-run check_collisions.py before loading any other slice. Label counts overlap for merged nodes. Documented in the README graph-model section.

## D6 Core edges default; soft edges opt-in and labeled "possible match". Keep raw link, status, dates, sourceID.
## D7 Role normalization (initial taxonomy, keep raw text)
Ownership: shareholder, owner, (ultimate) beneficial owner, beneficiary. Management: director, managing director, president, manager, chairman. Admin/legal: secretary, signatory, proxy, power of attorney, legal representative. Financial/compliance: auditor. Other/unknown: anything unclear. Never infer ultimate ownership from a single officer_of edge.
## D8 MCP: our own small server with fixed, purpose-built tools (not a generic text-to-Cypher server), so thresholds and scoring live in code we control. Runs inside the same deployment as the agent. Not exposed publicly. Built on MCP Python SDK v2 (mcp==2.3.0 pinned; v1 FastMCP API was renamed); name full-text indexes are created at server startup so every tool call stays read-only. Search runs raw + punctuation-stripped fulltext variants (union by node_id, exact-first) because RediSearch tokenizes commas/hyphens loosely. API envelope: every ask response echoes rid + question; live streams bypass the cache (fresh=1); the UI discards non-latest rids.
## D9 Deployment: guaranteed baseline = one-command local setup + small sample + import script + demo video. Try a live demo on a free host with a curated slice. FalkorDB free cloud is 100MB RAM, stops after 1 idle day, deleted after 7: backup only.
## D10 LLM use: development on Groq/OpenRouter; OpenAI only for the final demo; LLM picks tools and writes explanations, code does the graph work; cache demo answers; rate limit and daily cap on the public app. Agent stack pinned: langgraph==1.2.15 (decide→act loop), openai==3.31.0 (OpenAI-compatible client for groq/openrouter); no langchain-mcp-adapters — the agent drives the MCP stdio server directly with the mcp SDK client. MAX_LLM_CALLS_PER_RUN=8 enforced in code. Grounding (code-side, no LLM): every node_id, quoted name and country code in the answer must occur in tool results (degrees, question echo, link/role terms and name-embedded codes exempt); country name/code pairings checked against a small table; empty model finals are replaced from evidence, never returned silent. Ambiguity rule: path tools accept only ids returned by search_entity; fuzzy picks inject an ask-to-pick notice. Public app guards: per-request timeout (ASK_TIMEOUT_S=300), rate limit (ASK_RATE_PER_MIN=20, in-memory), daily LLM cap (DAILY_LLM_CAP=100, tracked in runs/llm_usage.json); demo answers cached in runs/cache.json with a cached flag shown in the UI.

Keep ingestion (CSV adapters and import) separate from the graph core (queries, scoring) and from the tool/MCP layer and the agent/UI. ## D13 Clickable disambiguation (pins)
Context: search_entity returns several exact-name candidates (e.g. two "Gary Pepper", two "Lee, Chung-Han"). The agent must not silently pick one. Decision: when a searched name has more than one exact match, the agent result carries a structured `candidates` list (for_name, node_id, name, labels, country_codes, degree_core, sourceID) derived from tool results ONLY; the UI renders each as a button. Clicking sends `pins` = {for_name: node_id} with the SAME question text (the box never changes) and shows "Using: name (label, country)". The agent treats a pinned name as resolved: it feeds the node_id straight to strongest_connection / shared_neighbors and refuses to re-search that name (deterministic node, no drift). Cache key stays the plain question text when unpinned (existing cache unchanged) and appends `|pins name=id` when pinned, so a pinned answer is cached separately. Candidates and pins are structured data on the API envelope; no new tool and no schema change. Grounding now also accepts node_id/name/degree found in `path.nodes`, because a pinned endpoint is never re-searched and its record only appears in the returned path.

## D15 Theme switching, the neutral highlight ring, and the edge-field contract
Switching mechanism: ONE mechanism — a `data-theme` attribute on `<html>` ("light"|"dark") mapped by CSS to a full token block; with no attribute stored, `@media (prefers-color-scheme: light) { :root:not([data-theme]) { ... } }` supplies the light block. A tiny inline `<head>` script applies a stored `oi-theme` before first paint; the toggle writes `oi-theme` to localStorage; a `matchMedia` change listener re-applies only while no manual choice exists. Cytoscape colours are data-mapped (they live on the elements), so a theme change re-reads tokens, rewrites node/edge data colours and re-applies the stylesheet (`cy.style().fromJson(graphStyle()).update()`) to every live instance.
Light palette (same cool-slate system, measured with a script, not by eye): page #f6f8fa, surface #ffffff, elevated #e9eef3, borders #d3dbe4/#a9b4c1, text #10161d/#3b4856/#5a6875, accent #0d7669, categories entity #1868b8, officer #2b8a3e, intermediary #a05a00, address #6741b8, merged #b02a5b, hub #c92a2a, unknown #6b7683. WCAG: text 4.7–18.2, categories ≥3.5:1 against both surfaces, warn text 8.4, edge-label text on its chip 18.2, ring 15.6.
Colour bug (Phase 3c, GALAXY ASIA → Tricor → ENFARI): the data was correct — each node has exactly one label — so the second colour was the replay step highlight's BORDER RING (`.flash`, 6px, accent; not a merged-label fill), and "no colour" was the old `.dim` opacity 0.18 still applied while the replay had not reached ENFARI. Fix: the highlight ring uses the neutral `--ring` token and is named in the legend ("selected / replay step"); dimming applies to EDGES only (0.25) and node fills are never dimmed. A node whose label is unknown or missing gets a dashed grey `cat-unknown` style plus a `console.warn`, never a silent default.
Edge-field contract: `strongest_connection`, `get_neighbors` and `shared_neighbors` also return `status`, `start_date`, `end_date` and the relationship's `sourceID` so the UI can show a per-edge card without a second query (`neighbors.py` keys the relationship field `rel_sourceID` to keep it apart from the neighbour node's own `sourceID`). Answers cached before this change keep only rel_type/link/role_category; the UI shows "—" for the missing fields.
Two-node actions are deterministic: `POST /connect {a, b, mode}` calls Q6/Q8 directly (backend/agent/actions.py), wraps the result in the agent envelope (trace step, limitations, excluded hubs) and adds no new query; `shared` edges carry explicit `source_id`/`target_id` so the star renders as a graph rather than a chain.

## D16 Union graph (`icij`) build — import root, persistence, timeout, soft-edge flags
- Union = Offshore Leaks + Panama Papers. Load: `--prepared icij --expect-nodes 838293 --expect-edges 1286362`; verified unique=838,293 CHECK OK, edges=1,286,362 CHECK OK, Portcullis core degree 37,338 OK (per-label sums exceed the unique total by 1,139, D4). N=838,293 shifts every score by ln(838294/278694) ≈ +1.10: T2Q1 9.35→10.45 (same 3-hop path), T2Q2 10.91→12.01.
- LOAD CSV is import-root-only: `../x`, absolute paths, and mounts nested under a `:ro` parent all fail (tested). Import root is therefore `DATA_DIR/import_root` with hardlinks: `prepared/*` at the root (offshore defaults unchanged) and `prepared_icij/*` under `icij/` (union uses `--prepared icij`).
- Persistence bug found + fixed: the image symlinks `/data/data → /var/lib/falkordb/data`; with only `/data` mounted, recreating the container lost every graph (it did; offshore was rebuilt in 14s from the untouched prepared folder). `falkordb-data` is now mounted at BOTH paths; verified by a forced recreate (health stayed 278,693).
- The image sets `FALKORDB_ARGS ... TIMEOUT 1000` (ms). Bulk loads need `GRAPH.CONFIG SET TIMEOUT 600000` first (resets on every container recreate). A load that dies mid-way needs `--drop` + re-run.
- `--drop` also wipes the full-text name indexes: run `ensure_search_indexes()` from `backend/graph/search_entity.py` after every reload; uvicorn startup alone does not recreate them (search returned 0 hits until it was run).
- D6 deviation (user-approved): tools traverse soft edges by default (no rel_type filter ever existed). Safeguard: any result whose path/neighbour edges include a soft rel_type now returns `includes_possible_match` + `possible_match_edges` (shared list in `backend/graph/rel_types.py`) plus a note naming the types; MCP schema text says "included by default"; the agent rule labels them "possible match".
