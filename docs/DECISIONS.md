- Relationships: node_id_start, node_id_end, rel_type, link, status, start_date, end_date, sourceID. All endpoints resolve to some node.
- Core rel types: officer_of 1.72M, registered_address 833k, intermediary_of 599k. Soft types are small (similar 47k, same_name_as 104k, same_as 4k, ...).
- Dev slice "Offshore Leaks": 278,693 nodes, 562,700 internal edges. "Panama Papers": 559,600 nodes, 721,822 edges. Slice by NODE sourceID, keep edges with both ends inside; ignore relationship sourceID (519k are empty).
- Hubs: p99 entities-per-officer 16, per-address 29, per-intermediary 357. Max about 36k (Portcullis TrustNet address/officer, Morning Star intermediary). 782 officers link to >100 entities; 26 addresses to >1000.

## D1 FalkorDB is central. If a feature works without it, the feature is wrong.
## D2 Hub awareness
Degree = how informative a link is, not whether a record is legitimate. Filter is configurable by node type, can be overridden by the user, and excluded hubs are shown in the explanation when they change the result. Degree = distinct neighbors, stored at import (core-only and all-edges counts).
## D3 Rarity-weighted relevance score
weight(v) = log((N + 1) / (degree(v) + 1)), N = nodes in the relevant population, degree over distinct neighbors. It is a connection relevance score, NOT a probability of kinship or wrongdoing. Show contributing nodes, edge types and degrees. Generate candidate paths with the hub filter inside the Cypher traversal, then rank the small set in Python. Do not assume FalkorDB has weighted shortest path: check the docs and test the installed version.
## D4 ID overlap policy: CONFIRMED option (a) — one node per ID with both labels
Evidence (Offshore Leaks slice): 1,139 IDs in both files (0.4% of nodes); all share identical normalized names, country_codes and sourceID; 53,011 in-slice edges (9.4%) touch them (43,304 officer_of + 8,450 intermediary_of + 1,193 registered_address + 64 soft), including the #2 hub Portcullis TrustNet (BVI) Limited (degree 36,254); in-slice type/role mismatch 0/0. Option (b) would delete real connectivity, so (a) wins. Never choose a record from rel_type alone. Store officer_name / intermediary_name separately ONLY when they differ, with name_mismatch=true (none differ in this slice). Verified on the Offshore Leaks slice ONLY — re-run check_collisions.py before loading any other slice. Label counts overlap for merged nodes. Documented in the README graph-model section.
## D5 Start with the Offshore Leaks slice; add Panama only after the end-to-end path works. Measure real memory and import time.
## D5b Loader choice: Cypher LOAD CSV (Phase 1c evidence)
IMPORT_FOLDER=/var/lib/FalkorDB/import (load-time default, confirmed live via GRAPH.CONFIG) mounted read-only from DATA_DIR/prepared (never raw CSVs). Chose LOAD CSV over falkordb-bulk-loader: no new dependency, dual-label merged nodes need Cypher control (bulk-insert derives one label per filename), explicit toInteger casts and batched per-file loads Viraj can explain. Full slice (278,693 nodes / 562,700 edges) loaded in ~14s; container ~537MB. Indexes on node_id per label created before nodes; edges resolve label-blind endpoints via indexed OPTIONAL MATCH + coalesce.
## D6 Core edges default; soft edges opt-in and labeled "possible match". Keep raw link, status, dates, sourceID.
## D7 Role normalization (initial taxonomy, keep raw text)
Ownership: shareholder, owner, (ultimate) beneficial owner, beneficiary. Management: director, managing director, president, manager, chairman. Admin/legal: secretary, signatory, proxy, power of attorney, legal representative. Financial/compliance: auditor. Other/unknown: anything unclear. Never infer ultimate ownership from a single officer_of edge.
## D8 MCP: our own small server with fixed, purpose-built tools (not a generic text-to-Cypher server), so thresholds and scoring live in code we control. Runs inside the same deployment as the agent. Not exposed publicly. Built on MCP Python SDK v2 (mcp==2.3.0 pinned; v1 FastMCP API was renamed); name full-text indexes are created at server startup so every tool call stays read-only. Search runs raw + punctuation-stripped fulltext variants (union by node_id, exact-first) because RediSearch tokenizes commas/hyphens loosely. API envelope: every ask response echoes rid + question; live streams bypass the cache (fresh=1); the UI discards non-latest rids.
## D9 Deployment: guaranteed baseline = one-command local setup + small sample + import script + demo video. Try a live demo on a free host with a curated slice. FalkorDB free cloud is 100MB RAM, stops after 1 idle day, deleted after 7: backup only.
## D10 LLM use: development on Groq/OpenRouter; OpenAI only for the final demo; LLM picks tools and writes explanations, code does the graph work; cache demo answers; rate limit and daily cap on the public app. Agent stack pinned: langgraph==1.2.15 (decide→act loop), openai==3.31.0 (OpenAI-compatible client for groq/openrouter); no langchain-mcp-adapters — the agent drives the MCP stdio server directly with the mcp SDK client. MAX_LLM_CALLS_PER_RUN=8 enforced in code. Grounding (code-side, no LLM): every node_id, quoted name and country code in the answer must occur in tool results (degrees, question echo, link/role terms and name-embedded codes exempt); country name/code pairings checked against a small table; empty model finals are replaced from evidence, never returned silent. Ambiguity rule: path tools accept only ids returned by search_entity; fuzzy picks inject an ask-to-pick notice. Public app guards: per-request timeout (ASK_TIMEOUT_S=300), rate limit (ASK_RATE_PER_MIN=20, in-memory), daily LLM cap (DAILY_LLM_CAP=100, tracked in runs/llm_usage.json); demo answers cached in runs/cache.json with a cached flag shown in the UI.

## D11 Module boundaries (cheap now, valuable later)
Keep ingestion (CSV adapters and import) separate from the graph core (queries, scoring) and from the tool/MCP layer and the agent/UI. No Offshore-Leaks-specific logic inside scoring or tool code; dataset specifics live in the adapter and in config. Name tools generically (e.g. strongest_connection, shared_neighbors), not after the dataset. Do not build extra generality beyond these boundaries during the hackathon.

## D13 Clickable disambiguation (pins)
Context: search_entity returns several exact-name candidates (e.g. two "Gary Pepper", two "Lee, Chung-Han"). The agent must not silently pick one. Decision: when a searched name has more than one exact match, the agent result carries a structured `candidates` list (for_name, node_id, name, labels, country_codes, degree_core, sourceID) derived from tool results ONLY; the UI renders each as a button. Clicking sends `pins` = {for_name: node_id} with the SAME question text (the box never changes) and shows "Using: name (label, country)". The agent treats a pinned name as resolved: it feeds the node_id straight to strongest_connection / shared_neighbors and refuses to re-search that name (deterministic node, no drift). Cache key stays the plain question text when unpinned (existing cache unchanged) and appends `|pins name=id` when pinned, so a pinned answer is cached separately. Candidates and pins are structured data on the API envelope; no new tool and no schema change. Grounding now also accepts node_id/name/degree found in `path.nodes`, because a pinned endpoint is never re-searched and its record only appears in the returned path.

Pinned to 3.34.4 (npm dist-tag `latest` at the time; version string verified inside the file). Bundled locally at `web/vendor/cytoscape.min.js`, served by the existing StaticFiles mount; no CDN, so the demo works offline. SHA-256 `081591ab735b2b6a3b31a3c60f8f3a3e2fee8c92939e0c7820ad1208571b6cd8`, 435,649 bytes. No other library is added. Node colour = label (Entity/Officer/Intermediary/Address, distinct hue for merged Officer+Intermediary); size = log2(degree_core); hubs (degree_core > threshold) get a double border and the hub colour; soft edges are dashed and labelled "possible match". ## D15 Theme switching, the neutral highlight ring, and the edge-field contract
Switching mechanism: ONE mechanism — a `data-theme` attribute on `<html>` ("light"|"dark") mapped by CSS to a full token block; with no attribute stored, `@media (prefers-color-scheme: light) { :root:not([data-theme]) { ... } }` supplies the light block. A tiny inline `<head>` script applies a stored `oi-theme` before first paint; the toggle writes `oi-theme` to localStorage; a `matchMedia` change listener re-applies only while no manual choice exists. Cytoscape colours are data-mapped (they live on the elements), so a theme change re-reads tokens, rewrites node/edge data colours and re-applies the stylesheet (`cy.style().fromJson(graphStyle()).update()`) to every live instance.
Light palette (same cool-slate system, measured with a script, not by eye): page #f6f8fa, surface #ffffff, elevated #e9eef3, borders #d3dbe4/#a9b4c1, text #10161d/#3b4856/#5a6875, accent #0d7669, categories entity #1868b8, officer #2b8a3e, intermediary #a05a00, address #6741b8, merged #b02a5b, hub #c92a2a, unknown #6b7683. WCAG: text 4.7–18.2, categories ≥3.5:1 against both surfaces, warn text 8.4, edge-label text on its chip 18.2, ring 15.6.
Colour bug (Phase 3c, GALAXY ASIA → Tricor → ENFARI): the data was correct — each node has exactly one label — so the second colour was the replay step highlight's BORDER RING (`.flash`, 6px, accent; not a merged-label fill), and "no colour" was the old `.dim` opacity 0.18 still applied while the replay had not reached ENFARI. Fix: the highlight ring uses the neutral `--ring` token and is named in the legend ("selected / replay step"); dimming applies to EDGES only (0.25) and node fills are never dimmed. A node whose label is unknown or missing gets a dashed grey `cat-unknown` style plus a `console.warn`, never a silent default.
Edge-field contract: `strongest_connection`, `get_neighbors` and `shared_neighbors` also return `status`, `start_date`, `end_date` and the relationship's `sourceID` so the UI can show a per-edge card without a second query (`neighbors.py` keys the relationship field `rel_sourceID` to keep it apart from the neighbour node's own `sourceID`). Answers cached before this change keep only rel_type/link/role_category; the UI shows "—" for the missing fields.
Two-node actions are deterministic: `POST /connect {a, b, mode}` calls Q6/Q8 directly (backend/agent/actions.py), wraps the result in the agent envelope (trace step, limitations, excluded hubs) and adds no new query; `shared` edges carry explicit `source_id`/`target_id` so the star renders as a graph rather than a chain.

## D16 Union graph (`icij`) build — import root, persistence, timeout, soft-edge flags
- Union = Offshore Leaks + Panama Papers. Load: `--prepared icij --expect-nodes 838293 --expect-edges 1286362`; verified unique=838,293 CHECK OK, edges=1,286,362 CHECK OK, Portcullis core degree 37,338 OK (per-label sums exceed the unique total by 1,139, D4). N=838,293 shifts every score by ln(838294/278694) ≈ +1.10: T2Q1 9.35→10.45 (same 3-hop path), T2Q2 10.91→12.01.
- LOAD CSV is import-root-only: `../x`, absolute paths, and mounts nested under a `:ro` parent all fail (tested). Import root is therefore `DATA_DIR/import_root` with hardlinks: `prepared/*` at the root (offshore defaults unchanged) and `prepared_icij/*` under `icij/` (union uses `--prepared icij`).
- Persistence bug found + fixed: the image symlinks `/data/data → /var/lib/falkordb/data`; with only `/data` mounted, recreating the container lost every graph (it did; offshore was rebuilt in 14s from the untouched prepared folder). `falkordb-data` is now mounted at BOTH paths; verified by a forced recreate (health stayed 278,693).
- The image sets `FALKORDB_ARGS ... TIMEOUT 1000` (ms). Bulk loads need `GRAPH.CONFIG SET TIMEOUT 600000` first (resets on every container recreate). A load that dies mid-way needs `--drop` + re-run.
- `--drop` also wipes the full-text name indexes: run `ensure_search_indexes()` from `backend/graph/search_entity.py` after every reload; uvicorn startup alone does not recreate them (search returned 0 hits until it was run).
- D6 deviation (user-approved): tools traverse soft edges by default (no rel_type filter ever existed). Safeguard: any result whose path/neighbour edges include a soft rel_type now returns `includes_possible_match` + `possible_match_edges` (shared list in `backend/graph/rel_types.py`) plus a note naming the types; MCP schema text says "included by default"; the agent rule labels them "possible match". Eton Consultants Group Ltd/Limited (290583–290763) verified: length-1 `similar`, flag true; T2Q1 core path flag false.

## D17 Multi-path listing — ranked alternatives + excluded reference path
- The tool already had the full candidate row set in memory; only its best row was returned. Now every distinct row (dedupe on node-id tuple + rel-type tuple) is returned best-first as `paths` (cap 8; `paths[0]` is byte-identical to the old `path`, so older callers and cached answers keep working). No new traversal: `CANDIDATE_LIMIT = PATHS_CAP + 1`, the spare row only reveals truncation (`paths_truncated`).
- Direct-link rows keep the existing `score: null` + score_note; ranking is a stable descending sort on the mean score (none last). A hub-blocked result adds ONE `reference_path` — the existing unfiltered SPpaths reference, whose query (REF_Q) now also returns edges and hops — marked `excluded: true` with `is_hub` on its nodes; it is never mixed into the ranked pages and never counted as an informative connection (agent SYSTEM rule + deterministic action text say so explicitly).
- UI: 4 per page in a 2x2 grid (single column narrow). Minis are card-shaped objects reusing the existing buildGraph/zoom/selection/side-card helpers unchanged; they are created on page show and destroyed on page leave, so at most 4 Cytoscape instances exist per card. The reference path renders in its own dashed "Excluded: only reachable through a hub" group. Cached answers without `paths` keep the legacy single-graph block.
- Verified (0 LLM): T2Q1 1 path 9.35; 142424→174769 8 paths (7×11.44 + 8.33); hub-blocked 185676→123355 reference len 2; no-path 123331→123345 clean; tool latency unchanged (0.165→0.168s worst case); MCP text ≤13.4k chars.

## D18 Help surface, question sets, neighbour star, grounded user ids
- Grounding: an id the USER typed in the question or pinned from a candidate list is ground truth — the model echoing it must never be flagged/replaced. `_ground(answer, evidence, question, pins)` adds question-text ids + pinned ids to the grounded set. Verified by replaying the stored S2 run (runs/run-20261017-204312.json) and one live run: `stripped:false`, "node 290583" survives in the answer.
- Neighbour star: `compose` adds `star` (centre, neighbours, excluded_hubs, note, soft flags; cypher removed) whenever get_neighbors ran. The UI renders it only when there is no `paths` block (ranked paths win when both exist). Star edges are undirected BY DESIGN: the tool result carries no relationship direction, so no arrowhead is drawn (`edge[?undir]` style); soft edges stay dashed "(possible match)". 4 neighbours per page, Prev/Next + "Showing x-y of N" + page dots, ONE live mini re-created per page (the path-mini model: created on page show, destroyed on re-page).
- Examples + help sidebar read ONE data file (`web/examples.json`): the chip tooltip is the example's exact question string, so chip and sidebar can never drift; "Try it" only fills the question box (responses never write to it). The question texts are cache keys (normalized lowercase + whitespace) and must not be "fixed" (e.g. "GALAXY ASIA LIMITED." keeps its period on purpose).
- Curated question sets are GENERATED: `scripts/build_questions.py` reads COMPLEX_QUESTIONS.md + TEST_QUESTIONS.md and writes `web/questions.json`; it FAILS if an included question has no graph label (docs ↔ page drift guard) and prints every dropped item with a reason. status = "agent-verified" only for ★ video picks and items whose docs say cached/agent-run, else "tool-verified only" (conservative). Items needing the other graph are shown but disabled with the server hint; there is deliberately NO runtime graph switcher.
- Help sidebar = native `<dialog>` + `showModal()`: focus trap, Esc close, backdrop, and focus return come from the platform (no hand-rolled focus code to get wrong). Fixed 44px "?" button upper-left; the banner gains left padding so they never overlap.
- `/health` returns `graph` next to `nodes`; the UI composes the badge text ("Graph: icij, Offshore Leaks + Panama Papers, 838,293 nodes"). Traced through `uvicorn` restart: the two running servers had to be restarted to serve the new code — the :8000 demo server runs under tmux `uvi8000`; the temporary :8001 icij check server was stopped after verification.

## D19 Cross-record identity questions — auto-pair, same-id guards, soft-only wording
- A single name resolving to exactly TWO exact hits from different sourceIDs is the two-endpoint question ("same company?"): `search_entity` auto-pairs them (`auto_pair` id_a/id_b + a note telling the model to call `strongest_connection`), sortable deterministically by node_id; trace carries the pairing. A pin no longer hides the other side: the pinned branch re-searches the raw name first, auto-pairs when possible, else returns the pinned row (a pin matches by name only, so it was previously able to pin one dataset's record for a two-dataset question). This is a heuristic on EXACT hits + distinct sourceIDs only — same-source twins (Eton) still ask the user to pick (correct ambiguity UX, verified live).
- `shared_neighbors` and `strongest_connection` reject id_a == id_b with a structured error that suggests the fix; `get_neighbors` takes one id, so its degenerate guard is an empty `node_id`. The agent SYSTEM prompt states the rule, and the fake-LLM replay shows the model recovering (guard → strongest_connection with the two ids).
- The neighbour-star block in `compose` requires `neighbors` + `hub_threshold` + a non-null `node_id` and NO `id_a` — error payloads share key names with the star but can never render as one (the old filter's overlap produced a null-centre "unknown label" star).
- Grounding (neutral language, rule 7) is enforced deterministically: when the only linking edges are soft (or the result carries possible-match flags) an identity claim ("the same company", "identical", a bare "strong") is replaced with "a possible match (not a confirmed identity)"; "shared neighbour" claims are removed when no shared result exists. Both actions are counted in the envelope (`identity_claims_replaced`, `shared_claims_removed`). Display fallback for unnamed nodes (addresses): `display_name()` → "unnamed <label> (id, degree N)" everywhere (tools, star, tables).
- Verified 2026-10-18 (10 product calls, gpt-4.1-mini): PEARL pinned/unpinned both end at `strongest_connection(10001004, 148317)` len 1 `same_as`, score "not applicable", wording downgraded; Eton regression green (both-pins `similar` edge, neutral wording). 8 stale cache entries deleted pre-verification (backup `runs/cache_deleted_pearl_eton.json`). Browser rendering (dashed edges, table label) pending Viraj.
